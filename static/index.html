Know what your API exposes.

API Sentinel checks whether a public API responds, how quickly it responds, and whether a focused set of HTTP security headers is configured. Every finding shows its evidence and a practical next step.

Assessment scope

Configuration, not exploitation.

  • Reachability, HTTP status, and response time
  • HTTPS, HSTS, CSP, content-type, and referrer headers
  • Redirect destination safety

API Sentinel does not authenticate, fuzz, exploit, or test business logic. A missing header is a hardening opportunity, not proof of a vulnerability.

            Plain-English guidance

            Understanding your results

            These notes explain what the scanner observed. They are not a substitute for a full security review.

            Why HTTPS matters

            HTTPS encrypts traffic between the client and API. Without it, credentials, tokens, and response data can be read or modified on the network path.

            What HSTS does

            Strict-Transport-Security tells browsers to use HTTPS for future requests to the site. It only applies over HTTPS and is most useful with a long max-age.

            When CSP helps

            Content-Security-Policy can limit content injection on browser-facing routes. It matters less for a pure JSON API, but remains useful for docs and HTML endpoints.

            Content-type and referrer controls

            X-Content-Type-Options: nosniff discourages MIME sniffing. Referrer-Policy limits how much URL information is shared with other origins.

            Status and latency

            A 2xx status means the application accepted the request. 4xx and 5xx responses still prove reachability but not success. Latency measures time to the final response headers, not full end-to-end processing.

            A missing header is a lead

            Missing hardening headers can increase risk, but they do not by themselves prove an exploitable vulnerability. Use the findings as review priorities.

            About the project

            A small, inspectable security assessment tool.

            API Sentinel is an API health monitoring and security configuration assessment tool designed to help users understand API availability, response performance, and HTTP security-header configuration.

            It performs a bounded, non-destructive request, checks a focused rule set, and explains every finding with evidence and remediation guidance. The interface is intentionally local and transparent so learners can see how the result was produced.

            Technology

            Python, FastAPI, Uvicorn, HTTPX, Pydantic, ReportLab, and a vanilla HTML/CSS/JavaScript dashboard. Reports are generated locally; there is no database or paid API.

            Score meaning

            The security score is an additive heuristic based on the scanner's severity weights. Higher values indicate more configuration risk. It is not a validated industry rating and cannot establish that an API is completely secure.

            Rule-based limits

            The scan reflects one request at one point in time. CDNs, WAFs, edge nodes, authentication requirements, and application behavior can change what is observed.

            Responsible use

            Assess only systems you own or have explicit permission to test. API Sentinel is an educational assessment aid, not an authorization to probe third-party services.
